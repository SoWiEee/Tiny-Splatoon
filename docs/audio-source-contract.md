# Native audio source contract

The native audio bank is exported from the source procedural engine. `tools/export-audio-source.mjs` imports `splat-ref/src/audio/audio.js`, then `splat-ref/src/game/kits/index.js` so every kit registers its sounds, and renders every registered SFX through Microsoft Edge's `OfflineAudioContext`. The same exporter renders all nine arrangements in `splat-ref/src/audio/music.js`, including each track's intro and one complete arrangement. The generated music is encoded as lossless 48 kHz stereo FLAC; its manifest stores the `loopFrom` frame and the arrangement end frame so playback starts with the intro and repeats at the source loop point.

SFX cues and loop beds are source-rendered at 48 kHz, stereo PCM16, seed 1234, with the source master processing enabled. One-shot renders retain 120 ms after the last sample above −60 dBFS. Loop renders remove the opening fade and blend the end seam. The manifest records source voice caps, pitch jitter, minimum repeat gaps, loopability, measured levels, hashes and durations. `--check` keeps the eight-LSB per-sample comparison for SFX and loop beds, then checks each music file's exact frame count and compares the full master-processed waveform using three bounds: at most 1,024 PCM16 LSB maximum difference, full-scale normalized RMS error at most 0.003, and Pearson correlation at least 0.9999. It also verifies exact track order, BPM, loop frames, asset hashes and formats, decoded music PCM hashes and asset file set. To keep the manifest replay stable when Edge's compressor shifts a loop's measured active duration or level, `--check` ignores only the loop `sourceActiveSeconds`, `sourcePeak` and `sourceRms` values; loop WAV hashes, sizes, formats and frame counts remain exact. An existing loop WAV within the eight-LSB source comparison remains canonical for both export and check, so its manifest hash matches the packaged asset. The wider music bounds account for measured variability in Edge's final Web Audio compressor stages, which is larger on some otherwise equivalent offline renders. Two fresh full-length 2,969,280-frame `battle` renders with the same source code and seed measured max differences of 28 and 616 PCM16 LSB; the latter pair had 0.002252 normalized RMS error and 0.9999306766 correlation. Comparing the checked-in lossless FLAC to that fresh render measured 616 LSB maximum, 0.002252 normalized RMS error and 0.9999306770 correlation. The retained bounds cover that measured spread with headroom. A synthetic one-frame circular shift of the source waveform is rejected (12,818-LSB maximum, 0.03321 normalized RMS error and 0.9935958 correlation), leaving a wide margin from the acceptance envelope. These measurements describe browser-render stability and do not claim sample-identical browser synthesis. The runner uses Edge's DevTools protocol and Node's built-in WebSocket without adding an npm dependency; set `EDGE_PATH` or `FFMPEG_PATH` when those programs are outside `PATH`. The exporter check and `tests/audio_source_render.test.mjs` require `ffmpeg` to decode the nine FLAC tracks; the native runtime uses miniaudio and has no ffmpeg dependency.

`restoration::AudioEngine` reads its cue list and source metadata from `assets/audio/catalog.tsv`. It keeps 48 bounded one-shot voices and 24 bounded loop voices, enforces each source cue's repeat gap and per-name cap, applies source pitch jitter, and supports pitch, 3D position, listener orientation, loop updates, fades, master/music/SFX buses, music ducking and crossfades. Source one-shots and loop beds are cached as PCM; voices own independent miniaudio cursors while borrowing the cached sample data. The nine music tracks stream from FLAC, use the source arrangement loop points, and share the same music bus. `Clear()` stops all active voices; `GameAudio::EndMatch()` fades managed loops and music out so scene changes do not leave audio running.

`restoration::GameAudio` routes the native actor triggers and state changes, match phase, `WorldVisualEvent`, boss move/phase, boss hit, and crablet transitions to source SFX and soundtrack tracks. The current gameplay routing is:

| Native input | Routed source audio |
| --- | --- |
| Actor `jump`, `special_leap`, `land`, `hit`, `shoot`/`stream`, `throw`, `charge_release`, `flick`, `slosh`, `blade_slash`/`blade_heavy`, `dodge`, `roll`, and `spawn` triggers | Movement, weapon, sub, hit and spawn cues; active-special shots resolve through the equipped special instead of a generic weapon cue. |
| Character touchdown and local movement state | `step_dry`, `step_ink`, or `step_enemy` from the grounded ink surface, with source speed volume and an 18 m remote-actor cull; submerged swimming, wall climbing, and enemy-ink contact manage their source loop beds. |
| Stage ambience | A `harbor_ambience` wash with occasional positioned gulls; `halyard` also gets gust-timed rigging clinks and distant ferry horns. Its independent audio random stream does not consume match or gameplay randomness. |
| Actor state edges for death/respawn, squid form, low ink/refill, special ready/activation/end | Source stings and actor-positioned sounds. Moving squid, charging splatling, and active jetpack/crab/storm/Booyah states manage source loop beds. |
| Main weapons and devices | Bow, blade, mitts, charger, splatling, and canopy actions use their source-specific shot/charge cues where native pose state exposes them. Torpedo, tracer, Waddle, boomerang and shaker devices update positioned loops and transition cues from their native device state; device loops stop on pause, device removal, and match teardown. |
| Sub throws and canopy state | Torpedo plays the source bomb-and-torpedo throw pair; tracer and boomerang use their own throw cues, while other throwables use `bomb_throw`. Brolly shots, open/close, damage, break, launch and regrow map to canopy cues. |
| Match intro/play/final minute/finish/results phases | Ready/go/timer/result stings plus `menu`, `battle`, `battle_final`, `results_win` or `results_lose` music. |
| World `explosion`, `bulletImpact`, `slamWave`, `stormStart`, and `burst` events | Spatial source explosion, wall impact, special slam, storm and splat cues. `beam` currently has no sound because its visual event has no firing actor ID, so it cannot distinguish charger shots from a Wail. |
| Boss phase, move telegraph/active/recovery, damage, stun, crablet spawn/death and defeat | Boss telegraphs, spatial impacts and loops, hit/crablet/death cues, a ducked defeat sting, and phase-specific `boss`, `boss_2`, or `boss_3` music. |

Boss move sounds use the simulation's body or barrel positions because the native simulation does not expose the named WebGL audio sockets. Source-specific loop `params` are not exposed by native simulation events; current managed loops use their source-rendered default timbre with runtime volume, pitch and position updates.

## Music transitions and remaining scope

Music changes between packaged tracks with the same BPM wait for the next source bar boundary, start the incoming track with an 8 ms fade, and fade the outgoing track over at most 250 ms. The native engine synthesizes the source riser live for the actual bar wait, using the source 2-second seeded white-noise buffer, exponential 400–7000 Hz band-pass sweep at Q 2.5, 220–1400 Hz saw sweep through a 3 kHz low-pass at Q 1, and the authored piecewise envelopes. It schedules the riser 20 ms after the request and ends it just before the downbeat. Different-tempo changes use a timed crossfade. Optional source recordings can be imported with `node tools/import-music.mjs splat-ref/songs`; the importer reads the source `songs/manifest.json`, copies supported WAV, FLAC or MP3 files under `assets/audio/songs/`, and writes `custom-music.tsv` rows as `track<TAB>gainDb<TAB>songs/<content-hash>.<extension>`. Native playback accepts recordings for `battle` and `battle_final`, applies the manifest gain, plays each recording once, and shuffles a per-track bag without repeating its last entry at bag boundaries. A missing or undecodable recording falls back to the packaged procedural track. Custom recordings have no source arrangement grid, so transitions to or from them use timed crossfades; `battle` begins another recording when one ends and `battle_final` remains one-shot. `GameAudio::Pause()` fades managed actor, device and Boss loops while leaving current music and the harbor wash running; the next update recreates state loops without replaying one-shot transition sounds. Boss phases select authored `boss`, `boss_2` and `boss_3` arrangements. The source `MusicEngine.setIntensity()` API has no native gameplay caller, so the native procedural tracks remain at the exported full-mix intensity of 1; no gameplay-driven stem changes are claimed. The full source SFX registry remains available in `AudioEngine` even when the native simulation has no matching event. In particular, the native match does not currently produce Zone scoring or XP progression events, so the exported `zone_*` and `xp_tick` cues have no native gameplay route. Beam visuals also still need the firing actor or weapon identity before GameAudio can distinguish a charger shot from Wail audio.

## Menu source repeatability calibration (2026-10-21)

Three fresh source menu renders reproduced two waveform variants. The source-to-source alternate measured max 775 PCM16 LSB, full-scale NRMSE 0.003792 and correlation 0.999758709318. Only menu uses measured bounds 1024 / 0.004 / 0.9997; the other eight tracks retain 1024 / 0.003 / 0.9999. No assets were replaced and there is no retry-until-pass path. A one-frame shift of the actual menu capture measured 6793 / 0.0133977 / 0.9969881 and fails all three menu limits. Source hashes, frame counts, loop points and FLAC decoding remain exact. Capture hashes and calibration are recorded in [the repeatability report](audio-menu-repeatability-2026-10-21.json). The original failed full check is retained above; the subsequent final full rerender passed.

## Final acceptance (2026-10-21)

The final one-pass `node tools/export-audio-source.mjs --check` exited 0: all 201 SFX, 31 source loop beds, nine music tracks, canonical hashes, frame counts, loop points, manifest and registry/index checks passed. No source audio WAV/FLAC was replaced. Per-track measurements are in [the final audio report](audio-acceptance-2026-10-21.json). Native optional-recording success/fallback and actor/device/weapon loop pause/resume/teardown passed `reference_audio_engine` after the test isolated one-shots from the loop-only assertion. Subjective listening and exact Boss socket spatialization remain outside this automated acceptance.
