# Native audio source contract — bounded cue slice

The current native slice contains 20 source-named cues: all seven UI cues, one primary shooter shot, hit marker, hurt, squid form in/out, jump, land, match ready/go/countdown/time-up, and win/loss results. `assets/audio/manifest.json` records their accepted source PCM measurements, format, byte hash, and active duration. Peak, RMS and active duration are measured from the accepted PCM bytes so tolerated browser float-mixer differences cannot make the manifest fluctuate. Each fresh source render is independently checked for non-finite/clipped samples and compared against those bytes.

`tools/export-audio-source.mjs` loads the real `splat-ref/src/audio/audio.js` in Microsoft Edge and renders each cue with `OfflineAudioContext` at 48 kHz, stereo PCM16, seed 1234, full source master chain, and unit bus gains. It keeps 120 ms after the last sample above −60 dBFS so the source envelope and short convolver tail remain intact. `--check` repeats the real offline render and compares each PCM16 sample within eight quantization LSBs, then checks the manifest and file set exactly; the observed Edge float-mixer variance reaches four LSBs on one fanfare, and this small allowance covers that while detecting audible drift. This runner uses Edge's built-in DevTools protocol and Node's built-in WebSocket; it needs no added npm package. Set `EDGE_PATH` when Edge is installed outside the standard Windows paths.

`restoration::AudioEngine` reads only the named WAVs in `assets/audio/` and uses the vcpkg miniaudio 0.11.22 high-level engine. It routes sounds through separate SFX/music sound groups and applies the source `pow(clamp(volume, 0, 1), 1.5)` curve to each group and the engine master. Each of the 48 bounded one-shot slots owns an independent `ma_audio_buffer_ref` playback cursor and `ma_sound`, while the immutable PCM is borrowed from the cached clip; cleanup uninitializes the sound, then its source, then the groups and engine before the cache is destroyed. `MA_SOUND_FLAG_NO_SPATIALIZATION` keeps the source-rendered stereo cues from being positioned as mono world sounds. When the pool is full, playback steals the oldest active one-shot. `Play(name, volume, bus)`, `SetVolumes(master, music, sfx)`, `Clear()`, `Metadata(name)`, and `ActiveVoices()` remain the integration and test seam. `Metadata` reports the decoded WAV format, duration, peak, and RMS; unknown names fail instead of substituting another sound. Device initialization remains fail-soft for the application, while metadata inspection stays available.

The native runtime consumes the source-rendered PCM, so the individual cue's synthesis, source effects, reverb and single-cue master processing are baked into each asset. Runtime controls still provide the three source volume buses. Multiple native clips are summed by miniaudio after that per-cue render; they do not yet pass through one shared source-equivalent compressor/convolver after mixing. This bounded slice is meant for UI and representative local match events rather than spatial world sounds.

## Not yet ported

The remaining source SFX and the approximately 53 kit-local procedural definitions are not included; those plus this slice account for the source's roughly 201 SFX definitions. The nine generated soundtrack arrangements and optional `songs/manifest.json` playback are not included. Boss audio event direction, phase music remapping, telegraphs, and managed loops are not included. The native slice has no pitch variation, spatial panning/attenuation, live loop handles, reverb sends, or crossfade/duck control yet. It therefore does not satisfy the full AUDIO-01–04 contract in `spec.md`.
