# Boss pose source contract

`tools/export-boss-pose-fixtures.mjs` executes the real locked `BossModel.update` and `BossAnimator` in Node. It exports 16 scenarios, 3,925 updates and 280 complete snapshots into `tests/fixtures/boss_pose_fixtures.json`. The exporter also checks source hashes; `--check` must reproduce the committed file exactly. It does not substitute native animation output as an expected value.

The scenarios cover idle, measured root translation and turning, aim, intro, roar, phase changes, hurt/weak flash, stun/recovery, death, and all six moves through telegraph/action/recovery. Each sample contains all 100 skin matrices, ten world-space hit spheres including radius/weak/active flags, and every numeric material uniform. The headless source uses its documented no-canvas stencil path; this test does not certify stencil texture rendering or terrain queries.

`src/game/BossPoseInput.hpp` carries the source animation state independently of OpenGL and match ownership. Gameplay maps its current state to that input. Pose calculation and hit-shape publication belong between the fixed-step boss update and combat queries; rendering a different number of frames must not change hit shapes or HP.

`tests/boss_pose_eval.cpp` advances the native pose through the identical input stream. `tests/boss_pose_oracle.test.mjs` compares all sampled skin-matrix elements, hit-shape fields and material uniform components with an absolute 0.001 threshold. Its optional third argument writes per-scenario failure counts, maximum error and first difference to a JSON report. Missing output fields fail the comparison. Asset triangle/bone counts and an ability to draw the mesh do not satisfy this contract.

The native adapter now evaluates the source animation channels, Float32 clip blending, springs, planted-foot gait, leg/claw IK and Verlet secondary chains. It publishes animated skin matrices and hit sockets from the fixed-step simulation sink before combat queries. The source rig export uses IBPR v2 double data for authored rest points and chain parents; reducing those inputs to Float32 changes the source segment lengths. Particle and channel storage still follows source Float32 writes. JavaScript Float32 reads promote to double for intermediate arithmetic: explicitly preserving that promotion in the clip blend fixed the remaining accumulated chain drift.

The strict native oracle passes **16 of 16 scenarios** across 3,925 updates and 280 snapshots at its original 0.001 threshold, after removing temporary diagnostics. It is registered in CTest as `reference_boss_pose`; the current report is [boss-pose-acceptance-report.json](../acceptance/boss-pose-acceptance-report.json). The earlier [boss-pose-checkpoint-report.json](../acceptance/boss-pose-checkpoint-report.json) is retained as historical evidence of the rest-rig checkpoint, not the current result.

The oracle covers the hull's matrices, ten sockets and numeric material uniforms. Rendering those uniforms, the Canvas stencil, live crablet animation, Boss hazard visuals, complete scene lighting and subjective motion quality require separate GPU/integration checks; this pose result alone does not accept the whole Boss mode.
