# Native projectile presentation

`CombatWorld` continues to own flight, collisions, paint and damage. `ProjectileRenderer` consumes its live rounds and the visual-event snapshot once per fixed tick; drawing cannot apply gameplay effects. The old projectile billboard and generic charger beam paths in `WorldEffects` are removed to avoid drawing each round twice.

`tools/export-projectile-visuals.mjs` reads the immutable source `Projectiles` constructors, actual materials and geometry. It exports the 14×12 sphere with the source glossy teardrop vertex deformation, physical fragment shader, source charger ribbon shaders, and the bow arrow/fletching/glow/streak, mitts fist and blade wave geometry/materials. Private kit constructors are exposed only in an in-memory module; source files are never rewritten. Standard materials use expanded bundled Three.js shader chunks and the existing source DFG lookup table; missing DFG data produced NaN lighting and was caught by the isolated GPU test.

`BuildProjectileBlobs` preserves the source muzzle pop, velocity-dependent tapered tail, wobble, blast swelling and satellite placement equations, including Float32 instance-buffer writes and the 700-instance bound. Twenty-four fixtures execute the real JavaScript `Projectiles._draw` and compare matrices, shape inputs, colors and counts at an absolute 0.00001 threshold. Runtime visual size variations derive from the shot's existing seed so presentation does not advance the gameplay RNG; the source browser's unrelated random stream is not claimed identical.

The actor muzzle adapter uses the live rig's right/left socket and rejects non-finite, distant or wall-obstructed sockets before falling back to the existing physics muzzle. `CharacterPose` now exposes the source's predictive aim socket from the weapon hold anchor, pitch, Y-X-Z rotation and weapon muzzle offset. `shotMuzzle` blends toward it by `1 - aimReady` below 0.98; rollers bypass the blend and dualies retain the separate live left-hand socket. This runs through the same finite/range/LOS guard in `WeaponRunner`. The native test covers unready/ready shooter, roller bypass and left-hand selection; a direct numeric JavaScript oracle for this new socket has not yet been added. Projectile shadow casting and complete bomb/device models remain outside this renderer's current coverage.

`reference_projectile_gpu` draws only the projectile under test in a hidden OpenGL 4.5 context. It requires visible pixels separately for the source teardrop/satellites, arrow, fist and blade wave, plus real charger-ribbon submission/expiration and no GL errors. Its captures are under `build/captures/projectile-*.png`. This is stronger than counting a projectile in the simulation or requiring unrelated FX to change some pixels; whole-scene reference image parity remains a separate acceptance requirement.

## Blade stop transition (v0.8.0)

Wall, shield and range termination emit a visual stop event with the projectile id. The renderer snapshots position, velocity, color and wave parameters without an actor pointer, then applies the source 0.14-second fade. A victim contact does not terminate the wave. World-time rollback clears retained fades; lodged bow glow also uses world time. The isolated GPU test checks visible wall fades, range-stop events, nonterminal hit behavior and expiry, including owner destruction during the retained fade.


## Snapshot preparation and shared upload (2026-10-25)

`ProjectileRenderer::Update` borrows one combat projectile view and fills its retained blob storage. The returning `BuildProjectileBlobs` interface remains compatible with all 24 source fixtures; the output overload clears and reuses caller capacity. Weapon trails also borrow one view per hook update. This removes repeated remote-view merging at these callers without adding a cross-caller invalidation cache.

The instance buffer is invalidated by Update and uploaded lazily by the first draw. Shadow and color passes share that upload; multiple updates before drawing only upload the latest snapshot. The GPU diagnostic intercepts actual GL buffer submissions, checks one upload across both passes, and checks invalidation on the next Update. Existing geometry, gameplay, colors and shader assets are unchanged.

Targeted CPU/GPU tests passed (2/2, 11.45 seconds), as did World FX GPU (7.46 seconds). A RenderDoc 1.46 capture is available locally at `build/captures/ink-module_capture.rdc`. The fixed seed 11 Tidewater diagnostic (1920×1080, medium, 180 warmup / 120 measured frames, GTX 1650 Max-Q) changed from 60.21 to 60.40 FPS, CPU p95 17.65 to 17.59 ms and GPU p95 17.57 to 17.53 ms. This short comparison does not establish a material FPS gain; the verified reduction is one instance upload instead of two for a shared snapshot.

## Shooter volume experiment (2026-10-25)

Regular `shot` projectiles from `shooter` use a native opaque material in `assets/shaders/ink-shot`. Following §3.3 of the supplied technical guide, each logical round has a local capsule plus two lobes joined by polynomial smooth union. The tail stretches and separates with normalized age; seed controls asymmetric placement. Zero to three smaller mesh drops provide secondary detail. Finite-difference field normals feed directional/hemisphere lighting and a restrained wet highlight. Other weapon types retain the source path and its 24 numeric fixtures.

Near-view primary volumes raymarch within a conservative sphere proxy, at most 48 steps with a 0.70 distance multiplier. Local-space rays are reconstructed from the current viewport and inverse clip transform, including orthographic projection. The shader writes actual surface depth, not proxy depth; back proxy faces retain coverage when the camera enters the bounds. Below a two-pixel projected radius the primary uses a mesh; two to five pixels gradually reduces the extra lobes. Secondary drops always use meshes. Fusion is local to one logical round: separate shots and opposite teams are not joined into a global field.

For §3.4, seeded low-frequency curves move the capsule ends and lobe centers and modulate their radii by a small fraction of the body radius. The muzzle volume grows in 35 ms, with a decaying launch impulse and speed-dependent stretch bounded to 1.4–2.2. Its visual radius is increased by 16% before the short impulse expansion. Detached drops release at 25/45/65 ms, with relative backward/outward speeds of 12%/5% of the logical round's speed. All changes are presentation-only and use existing shot seed/age; the gameplay RNG, velocity, collision, damage and ink cost are preserved.

Update prepares both groups into the same retained 700-instance snapshot. Mixed weapon draws use two material batches with a base-instance offset; shadow and color still share one upload. The isolated GPU test checks both camera angles, connected/stretched/separated silhouettes, front/behind depth occlusion, camera-inside bounds, orthographic rays, small-ink mesh LOD, mixed batches, upload reuse and the new volume's shadow. CPU assertions cover deterministic output, finite transforms, launch impulse decay, prompt growth, smooth secondary motion and instance bounds.

Shooter collision events retain the projectile seed and identify their visual source. Geometry hits use the surface normal; actor/Boss hits eject back along the incoming direction. `WorldEffects` dispatches a short surface-aligned crown and four to seven drops using an event-local seed. The new visual-only drop flag prevents secondary paint, ripples or bounce callbacks. Legacy recipe ordering remains unchanged. Combat flight, hit detection, damage, ink cost and the existing FacePaint/RT path are unchanged; the old shooter flight trail is skipped to avoid duplicate droplets.

Six targeted tests passed after the §3.4 changes: source projectile fixtures, shooter impact recipe, projectile GPU, combat world, World FX GPU and World FX oracle. The 180-frame fixed-step comparison records 15 real impacts and paint version 4 on both sides; its gray diagnostic floor does not display the RT paint texture. Updated frames and the half-speed comparison video are in `build/captures/shooter-sdf/` and `build/captures/shooter-sdf-comparison.mp4` (left: source presentation, right: local SDF). Close-up evidence includes `shooter-sdf-fused.png`, `shooter-sdf-neck.png` and `shooter-sdf-breakup.png`.

The initial mesh experiment recorded 59.72 FPS, CPU p95 17.78 ms and GPU p95 17.78 ms, against the preceding 60.40 FPS / 17.59 ms / 17.53 ms snapshot baseline on GTX 1650 Max-Q. The final SDF/impulse short run records 60.70 FPS, CPU p95 17.32 ms and GPU p95 17.39 ms (`build/reports/ink-v088-impulse.json`), using the same seed 11 Tidewater scene, medium graphics, requested 1920×1080 resolution and 180 warmup / 120 measured frames. These runs show normal timing variation, not an established speedup, worst-case result or statistical performance claim. Final visual acceptance and wider weapon coverage remain separate work; no screen-space fluid, SPH or new dependency is added.
