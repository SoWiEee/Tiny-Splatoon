# 多人連線契約

原生多人使用 GameNetworkingSockets direct-IP 傳輸及獨立房間服務。服務處理私人房碼、房間成員、隊伍、準備與封包轉送；玩家房主程序獨立於房間服務。驗收範圍見[還原進度](../restoration-progress.md)。

## 房間與大廳

房碼為五字元，房間最多八人，名單順序穩定並保留玩家 ID、隊伍、準備、公開裝備／外觀及房主身分。RmlUi 提供建立／加入、取消、錯誤、複製房碼、換隊、準備、招呼與房主設定；本機服務閒置 180 秒後自行結束。服務最多 32 房／128 條連線，玩家每秒最多 90 則訊息；比賽斷線 20 秒、大廳斷線 150 秒後移除，兩秒 heartbeat 保持大廳連線，最後一人離開後清理房間。載入最多等待真人玩家 12 秒。服務、客戶端及選單有容量限制、非阻塞輪詢與訊息欄位檢查；公開 profile 不含 XP、存檔路徑或私人設定。

大廳有來源巷弄場景及自動加入、換隊、站定位、準備、招呼、倒數與彈射演出；不提供自由走動控制。GUI 可啟動 loopback 服務；區網服務需由命令列指定可連線 IP。所有玩家需連到相同服務位址。

## 比賽權責與同步

- 玩家模擬自己的角色；房主管理 AI、比賽時計、Zones、Boss 及結算。遠端投射物、角色與裝置快照只供呈現，不會在接收端重算傷害或塗地。
- Actor、投射物、裝置及特殊狀態以 20 Hz 快照呈現；重要 gameplay 事件使用可靠傳輸。插值保留 sender timeline、速度 Hermite、85–300 ms 緩衝與最多 180 ms 外推。
- 命中確認與事件依 owner、sender、序號及對局 epoch 去重。受擊角色 owner 套用一次傷害；裝置命中回到 owner，Boss 命中交房主。種子墨水事件逐筆重播。
- 普通場玩家離線時由房主將原 actor 交給 AI；Cargo 移除角色且不補 AI。房主離開後由下一位玩家承接目前 Boss／Zones 狀態並建立新的 AI brain。
- 結果由房主統一，結束後可回到同一房間再開一局；訪客不能結束其他人的對局。XP 以房間／對局識別資料防止重複結算。

## 部署限制

可靠訊息單包上限 64 KiB，收送佇列有容量上限，超載會回報錯誤；過期的不可靠快照可以丟棄，等待下一份狀態。每位 owner 的呈現快照最多包含 24 個投射物、12 個裝置、12 個特殊物件及每個 Tracer 64 個路徑點；這不限制可靠墨水與命中事件。

GNS direct-IP 不提供公開房間查找、Steam SDR、NAT 穿透或帳號認證。
