# Remaining-special source contract

`tools/export-remaining-specials-source-fixtures.mjs` runs the real `Actor`, `SpecialSystem`, special objects, and Crab Rig prop construction from `splat-ref`. The exporter supplies a headless stage, deterministic ground/wall queries, no-op render/audio sinks, and a render-only canvas stub for the return-marker badge. Its device-damage sink forwards back to the real `SpecialSystem.areaHit` hook so special-object chains remain active. It keeps Three.js UUID generation separate from the seeded gameplay random stream. It does not translate special definitions into expected results: recorded poses, event payloads, hit calls, object snapshots, and fixed-step counts come from source execution.

The generated artifacts are `tests/fixtures/remaining_specials_source_fixtures.json` for inspection and `tests/fixtures/remaining_specials_source_fixtures.hpp` for native assertions. The JSON records SHA-256 hashes for the source config, Actor, SpecialSystem, physics, weapons, and Crab special-prop module. Regenerate them with `node tools/export-remaining-specials-source-fixtures.mjs`; use `node tools/export-remaining-specials-source-fixtures.mjs --check` to verify they match the current source. A source edit that changes a behavior or hash requires re-running the native acceptance test.

The native acceptance test uses real `PlayerSimulation` and `CombatWorld` objects on a controlled flat stage, with a single solid wall only for Zipcaster. Victims remain stationary, which keeps the measured areas and projectile paths deterministic. It compares integer frame counts exactly and uses a default `1e-6` tolerance for floating-point values; the Crab muzzle is checked against the separately generated source prop vector at that same tolerance. Its fixture values represent the controlled source scenarios above, not general matchmaking, animation, or rendering behavior.
